# 世系 · 家族谱系图

一个零依赖的静态族谱阅读器。以 SVG 树状图呈现代际关系，支持多套族谱切换、重点人物标记、人物长文、分支折叠、平移与深链跳转。

页面不依赖服务器：**直接双击 `index.html` 即可阅读**。数据在构建时打包进 `data/lineages.js`，因此 `file://` 下也不会遇到跨域读取问题。

内置六套示例：

- **总览**：460 人 / 59 代 / 358 组亲缘，五帝至秦亡的合谱；除本纪诸系外，已并入吴、鲁、蔡、曹、卫、宋、郑、晋八支世家。
- **五帝本纪**：21 人 / 10 代 / 14 组亲缘，据《史记·五帝本纪》整理。
- **夏本纪**：21 人 / 18 代 / 18 组亲缘，据《史记·夏本纪》整理；自黄帝画起，禹为第五代。
- **殷本纪**：49 人 / 34 代 / 46 组亲缘，据《史记·殷本纪》整理；自黄帝画起，成汤为第十八代。
- **周本纪**：60 人 / 51 代 / 50 组亲缘，据《史记·周本纪》整理；自黄帝画起，后稷至季历的先公世系一并收入，文王为第十九代，至赧王而周亡。
- **秦本纪**：68 人 / 54 代 / 52 组亲缘，据《史记·秦本纪》《秦始皇本纪》整理；自黄帝起，至子婴降汉。

## 快速开始

直接双击 `index.html`。

如果习惯用本地服务器，也可以：

```bash
cd family-tree
node serve.mjs
# 打开 http://127.0.0.1:4173
```

修改 `data/manifest.json` 或任一谱系 JSON 后，需要重新生成静态数据：

```bash
npm run build:data
```

然后刷新页面。**只改 JSON 不重新生成 `data/lineages.js`，页面不会更新。**

## 数据格式

### 1. 族谱目录 `data/manifest.json`

```json
{
  "schemaVersion": 1,
  "site": {
    "title": "世系",
    "subtitle": "LINEAGE ARCHIVE",
    "description": "以树状谱系阅读古代帝王世系。",
    "defaultPortrait": "assets/portrait.svg"
  },
  "defaultLineage": "five-emperors",
  "lineages": [
    {
      "id": "five-emperors",
      "file": "data/five-emperors.json",
      "title": "五帝本纪",
      "shortTitle": "五帝",
      "period": "传说时代",
      "peopleCount": 25
    }
  ]
}
```

- `defaultLineage`：首次打开时载入的族谱 `id`。
- `file`：谱系 JSON 的源文件路径，供 `npm run build:data` 读取；页面运行时不直接请求它。
- `peopleCount`：侧栏展示用的参考数字；实际统计以谱系文件为准。
- `site.defaultPortrait`：全站统一半身像；单套谱也可用自己的 `defaultPortrait` 覆盖。

### 2. 单套族谱

```json
{
  "schemaVersion": 1,
  "id": "five-emperors",
  "title": "五帝本纪",
  "subtitle": "《史记·五帝本纪》帝系",
  "shortTitle": "五帝",
  "period": "传说时代",
  "description": "一句话说明这套谱的范围。",
  "source": "资料来源与取舍说明。",
  "defaultPortrait": "assets/portrait.svg",
  "generations": [],
  "people": [],
  "unions": [],
  "extraLinks": []
}
```

#### `generations`

```json
{ "index": 1, "label": "第一代", "note": "黄帝之世" }
```

`index` 是全站统一的绝对代次，以黄帝为第 1 代；六套谱都从黄帝画起，同一人物在各谱与总览里代次一致（禹恒为第五代，成汤第十八代，文王第十九代）。人物通过 `generation` 对应到这里。`label` 与 `note` 只显示在画布左侧的代际标记中。

#### `people`

```json
{
  "id": "huangdi",
  "name": "黄帝",
  "aliases": ["轩辕", "公孙轩辕"],
  "generation": 1,
  "importance": "key",
  "honor": "emperor",
  "bio": [
    "第一段小传。",
    "第二段小传。"
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 全局唯一，用于关系引用与 URL 深链，建议使用小写英文/拼音 |
| `name` | 是 | 显示名 |
| `generation` | 是 | 所属代，必须存在于 `generations` |
| `aliases` | 否 | 别名数组；人物卡只显示第一个，详情显示全部 |
| `importance` | 否 | `key` / `notable` / `normal`，默认 `normal`；只有 `key` 进入左侧索引 |
| `honor` | 否 | `key` 人物的外观类别：`emperor`（帝王，金边 + 王冠）或 `other`（其他重要人物，朱红细边 + 五角星）；缺省按 `other` 处理 |
| `indexed` | 否 | 是否进入左侧索引，默认 `true`；设为 `false` 时画布外观与同类完全一致，只是不占索引位置（用于「是帝王但不进索引」的第二类） |
| `title` | 否 | 左侧索引里显示的称号，缺省用 `name`。用于 `name` 只写名（如「昌」）而索引需要显示「文王」的场合 |
| `bio` | 否 | 字符串或字符串数组；详情正文，数组会分段显示；没有单独的首段提要 |

**重点人物**：`importance: "key"` 会在画布上做标记。`honor: "emperor"` 用金色边框与线条王冠，`honor: "other"` 用较细的朱红边框与线条五角星；左侧索引按“帝王 / 其他重要人物”分组。**进入索引的人，卡片另加底色**：帝王淡藤黄、其他淡朱，图标同时改用深青铜／深朱描边，免得亮金、亮朱压在底色上看不清。写 `"indexed": false` 的第二类帝王保留同样的边框与图标，但卡片仍是白底、也不进索引（不计入分组数字），于是「有没有底色」就是「在不在索引里」。`notable` 只用于语义分层，当前不额外标记。

当前索引口径：五帝本纪收 黄帝、颛顼、帝喾、尧、禹、舜，另以「其他重要人物」收 鲧（挚只描金边不入索引）；夏本纪收 黄帝、颛顼、禹、启、桀；殷本纪收 黄帝、帝喾、成汤、太甲、武丁、纣，另收 契；周本纪收 黄帝、帝喾、文王、武王、成王、厉王、宣王、幽王、赧王，另收 弃、古公亶父、周公旦；秦本纪收 黄帝、颛顼、昭襄王、始皇帝，另收 非子、造父、襄公、穆公、孝公。其余君主（挚、季历及多数秦君）只描边、不入索引。总览与各分谱同步：弃、契、古公亶父在总览里同样是「其他重要人物」；并入世家后，总览另收 太伯（吴太伯）、季札、阖闾、夫差、伯禽、蔡叔度、曹叔振铎、卫康叔、郑桓公、唐叔虞、晋文公、宋襄公、宋王偃 为「其他重要人物」。

周本纪的命名约定：`name` 只写名（昌、发、诵、胡、静……），王号放 `aliases` 首位，卡片于是读作「昌 / 文王」；左侧索引另用 `title` 显示王号，免得侧栏只剩单字。周室不收配偶，只列父子与兄弟相继。

秦本纪另有 `data/qin.json`，自黄帝起，与总览同一代次：`name` 写《秦本纪》《秦始皇本纪》给出的本名（任好、嵤、政、胡亥、扶苏、将闾、成蟜、婴），公号、王号放 `aliases` 首位，卡片于是读作「政 / 秦始皇」「婴 / 子婴」；单字名或本名不彰者另用 `title` 供索引显示（政 → 始皇帝、任好 → 穆公）。原文未载本名的君主仍以公号为 `name`（襄公、宁公、简公……）。`bio` 一律照录两篇原文；代次只按原文明写的父子、祖孙关系推进（如「其玄孙曰中潏」「竫公子立，是为宁公」「立二世之兄子公子婴为秦王」）。子婴原文只说是「二世之兄子」，未言其父，故在图上挂到祖父 政 名下、按隔两代落位。

世家分支只收世系可考的八种，都挂在总览里：吴（仲雍至夫差）、鲁（伯禽至顷公）、蔡（蔡仲至侯齐）、曹（曹太伯脾至伯阳）、卫（康叔封至君角）、宋（微仲至君偃）、郑（桓公友至郑君乙）、晋（唐叔虞至静公俱酒）。各按《世家》的「某卒，子某立」逐代落位；同辈兄弟相继（弟及）不增代，仍挂在前一代名下，如鲁 炀公、魏公、献公、武公、孝公、釐公、定公，蔡 哀侯、平侯，曹 幽伯、戴伯、缪公、成公、隐公、声公、靖公，卫 州吁、黔牟、殇公、悼公，宋 微仲、炀公、穆公、殇公、桓公、文公、偃，郑 子亹、子婴、襄公、成公、共公、繻公、郑君乙，晋 成师、鳝、称、缗、黑臀、小子。燕、楚、越、陈、田齐、魏、韩等篇或只称「与周同姓」，或中间世次失载（如「自召公已下九世至惠侯」「弗能纪其世」），按「黄帝后代 + 代数明确」的要求暂不入谱。

宋、晋两支的世次与周室并不同步：宋自微子起算，微子与纣同为帝乙之子，而殷系自黄帝下来已比周室多出十余代，所以宋君偃落到第五十九代，比周赧王（第五十一代）还低八代；晋自唐叔虞起算，世系压缩，静公只到第四十七代。这是《史记》原文世系本身的差异，不是填错。

人物卡只显示姓名与第一个别名；简介抽屉只显示姓名、全部别名与 `bio`，不再显示身份标题、标签、亲缘列表或上一/下一重点。

半身像统一使用 `defaultPortrait`，不按人物单独配置，以保持谱系视觉一致。

#### `unions`：亲代到子代的关系组

这是关系建模的核心。一个 union 表示一组父母与一组子女：

```json
{
  "id": "u-huangdi-leizu",
  "parents": ["huangdi", "leizu"],
  "children": ["xuanxiao", "changyi"],
  "label": "黄帝与嫘祖之子"
}
```

- `parents` 与 `children` 都是人物 `id` 数组，长度至少为 1。
- 一对一、一对多、多对一、多对多都落在同一种结构里。
- 每个子代必须属于比所有父母更晚的代；校验会检查这一点。
- `label` 可选，用于关系说明。
- 同一个人可以出现在多个 union 中。例如古公亶父既与太姜生季历，也与太姜之外的关系生太伯、虞仲；本谱用两个 union 表示。
- `parents` 并不强制表示婚姻，只表示“这组亲代共同对应这些子代”。单亲关系就只写一个 parent。
- 同父异母、生母未详等情况，可以用多个 union 或 `label` 说明。

渲染全部使用正交直线：血统主亲从卡片底部垂直落到水平总线，子女再从总线垂直落到各自卡片顶部；一组亲缘只有一条水平线。配偶不参与这条总线，只在两张卡片中部横连一段短婚配线，否则配偶会垂直落到总线上，看起来像子女从配偶那里垂下来。

单亲独子（一代只有一个人传下来）时，子代与父代严格同轴：连线是从父代卡片下沿直达子代卡片上沿的一条竖线，中间既不横折也不经过总线。

多子排布采用「逐个贴紧」：从左到右依次放置，每一对相邻子女只按这两棵子树真正要相撞的那一层让开距离，不再由最宽的一对决定全体步长；放完整组再挪回父节点下方（首末子节点中点对齐）。于是同一代的后代在互不碰撞的前提下尽量靠拢，画布宽度随分支多寡平缓增长，而不是被最宽的一对撑开。没有子嗣的人不单独占位，卡片就停在总线下方。

纵向节奏固定：每一代的高度完全相同（`ROW.pitch` = 220），等于卡片高 168 + 向下延伸的竖线 `ROW.stem` 33 + 分支线到子女的 19。不再按“这一层往下要画什么”逐代调节。

人物卡 132 × 168：顶部 94 的人像、姓名（27px）、别名（17px）三段。字体用 `--card-face`（宋体系统，Win 走 SimSun、macOS 走 Songti SC），横细竖粗、字形方正，缩到 70% 左右仍能辨认；楷体在小字号下笔画会糊在一起，所以没有沿用。

#### `extraLinks`：非亲子关系

```json
{
  "from": "yao",
  "to": "shun",
  "type": "succession",
  "label": "禅让"
}
```

用于禅让、让国、配偶、师徒等不好塞进亲子树的关系。`from` 与 `to` 都是人物 `id`，箭头指向 `to`。内置示例使用：

- `succession`：禅让
- `spouse`：配偶
- `abdication`：让国

`type` 可取任意字符串，当前主要用于分类。为了避免虚线穿过人物卡，`extraLinks` **不画到树状图上**，也不在详情里展示；它是为后续扩展保留的资料字段。

## 宽代与长谱怎么读

一代人很多时，横向宽度会迅速膨胀。页面组合了这些手段：

- **拖拽平移 / 滚轮上下滚动**：滚轮不再缩放，只负责移动图面；`Shift + 滚轮` 横向移动。
- **全览**：缩放到能看到整棵树；适合看结构，不适合读小字。
- **右下缩略图**：点击或拖动定位到全图任意位置。
- **画布左侧代际标记**：每一代在树左侧显示代次、世次说明与人数，随图面上下移动。
- **左上角重点索引**：只分“帝王 / 其他重要人物”两组，直接跳到重点人物，不必在宽图里寻找。
- **详情内“折叠后裔”**：隐藏该人物全部后代，空出来的代会被移除；顶部“展开全部”恢复。
- **深链与重点跳转**：重点索引和 `#/谱系id/人物id` 深链都可以直接定位人物。
- **工具栏 + / −**：仍可按可视区域中心缩放。

初始比例会优先保证姓名可读：只有整棵树在全览时仍足够大，才直接全览；否则以可读比例从第一代开始，用户再自行平移或全览。

## 交互与深链

- 点击人物卡：打开右侧详情。
- 拖拽画布：平移；滚轮：上下滚动；`Shift + 滚轮`：横向滚动。
- `Esc`：关闭详情；移动端也会关闭侧栏。
- `f`：全览。
- `+` / `-`：以当前可视区域中心缩放。
- 地址栏使用 `#/谱系id/人物id` 深链，例如：

```text
file:///D:/Coding/family-tree/index.html#/five-emperors/huangdi
file:///D:/Coding/family-tree/index.html#/zhou/wenwang
```

直接打开深链会载入对应族谱、定位并打开人物详情。

## 校验与开发

```bash
npm run build:data  # 把 data/*.json 打包成 data/lineages.js
npm run check       # JavaScript 语法检查
npm run check:data  # 校验 manifest 中所有族谱的引用与代际关系
```

运行时 `validateLineage()` 也会做同样的检查；数据有问题时页面显示错误面板，而不是静默画出错误结构。

如需新增一套谱：

1. 复制一份谱系 JSON，改 `id`、`title` 与人物/关系。
2. 确保每个人物的 `generation` 都在 `generations` 中，且子代代次晚于亲代。
3. 在 `data/manifest.json` 的 `lineages` 中增加一项，`file` 指向新文件。
4. 运行 `npm run check:data` 与 `npm run build:data`，刷新页面。

## 已知限制

- 极长的单链世系（例如周本纪 33 代只有一条主线）全览时必然缩得很小，姓名不可读；应配合重点跳转和缩放使用。
- 布局是为“代际行 + 主亲轴树”设计的，不是通用图布局；单亲单子会保持同轴，多子围绕主亲展开，但极复杂的多对多交叉关系仍可能需要人工调整 `generations` 或拆分 union。
- 统一半身像是无五官的圆头半身剪影，不区分人物相貌；这是刻意的视觉统一，不是遗漏。
- 没有后端、账号或编辑界面，数据以 JSON 文件为准；修改后需重新运行 `npm run build:data`。
